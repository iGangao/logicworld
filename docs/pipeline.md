# 情景化任务生成与校验流程

本文档说明如何将 LOGICWorld 的紧凑任务指令改写为自然情景，同时保持任务语义和
`verify` 验证目标不变。README 提供使用摘要；本文档保留完整约束、当前实现边界与
后续质量保障计划。

## 目标与不可变约束

改写必须同时满足：

1. **任务语义不变**：故事要求的动作、对象、数量、顺序和分支与原始 `task` 等价；
2. **验证目标不变**：按故事正确执行后，应满足原记录的 `verify` 表达式；
3. **源数据不变**：不覆盖 `data/logicworld/test.jsonl`；
4. **结果可追溯**：输出保留 `task_original`、源字段和生成审计信息。

`verify` 是由受限谓词构成的 Python 布尔表达式，主要包括 `saw`、`located`、
`exist`、`count`、`count_receptacle_items`、`visited`、`hold`、`toggled`、
`opened`、`verify_order_*` 和 `verify_category_place_task`。

## 流程概览

```text
data/logicworld/test.jsonl
              │
              ▼
[1] 读取 task / verify / task_type
              │
              ▼
[2] 提取对象、数量、顺序与放置约束
              │
              ▼
[3] 构建约束感知提示词并生成故事
              │
              ▼
[4] 确定性规则检查 ── 失败 ──► 携带原因重新生成
              │ 通过                    │
              │                    最多尝试 3 次
              ▼                         │
[5] 追加写入 JSONL ◄────────────────────┘
              │
              ▼
[6] 形式化校验、独立评审与人工抽检（规划中）
```

## 改写契约

### 情景包装

- 可以增加人物、动机和背景，用来解释“为什么需要完成任务”；
- 执行动作的主体始终是第二人称 `you`，人物只提供动机；
- 故事使用英文、保持单段，长度随原任务复杂度调整；
- 若引入人物，应在任务指令之后自然收束，例如
  `Now you come and help <character> complete the task.`。

### 语义保真

- 保留全部条件及兜底分支，不把任务改写为编号式决策树；
- 条件必须与其控制的动作绑定，不能把动作改成无条件要求；
- 不得提前断言存在性、数量、容器关系以及是否看到或到访；
- 不得增删目标对象、操作动作或 fallback 行为；
- 同一条件控制的一组动作必须整体保留，不能拆分或重组；
- 不得声称某个条件本身即可完成任务。

### 精确表述

- 对象实例名逐字保留，不使用近义名称替换；
- 数量和比较关系必须精确，例如 `count('x') > 4` 表述为 `more than 4`；
- `order_*` 任务显式保留全序，非顺序任务不得擅自增加先后关系；
- 明确保留对象与容器之间的 `on` / `in` 关系；
- 显式表达否定，嵌套否定要保留括号所表示的逻辑层次；
- 区分 `saw`（搜索中看到）与 `visited`（实际到访）；
- 不泄漏 `verify`、`task_type`、house ID 等数据集元信息。

## 当前实现

### 约束提取

`scripts/generate_stories.py` 从 `verify` 中提取对象名和数值比较，并针对以下任务
进行专项处理：

- `order_*`：解析对象及优先级，检查它们在故事中的出现顺序；
- `num_place`：提取具体容器实例、对象和精确数量；
- `category_place`：提取容器、非零数量目标，并禁止出现零数量对象；
- 条件任务：标记所有顶层析取分支共同要求同一目标的可疑验证式；
- 数量任务：标记 `count_receptacle_items(...) < 0` 这类不可满足分支。

后两项是源数据审计标记，不会自动改写 `verify`，也不代表故事生成失败。

### 生成与断点续跑

生成器使用与 OpenAI Python SDK 兼容的 Chat Completions 接口。凭证仅从环境变量
`OPENAI_API_KEY` 和 `OPENAI_BASE_URL` 读取，不写入代码或数据。

```bash
export OPENAI_API_KEY=...
export OPENAI_BASE_URL=...
python scripts/generate_stories.py --batch 10
```

默认输出为 `data/logicworld/test_stories.jsonl`。脚本以源数据行号 `_index` 识别已经
处理的记录，因此可以重复运行并继续生成尚未完成的条目。

### 确定性规则检查

当前检查覆盖：

- 必需对象名是否逐字出现；
- 数值比较中的关键数字是否保留；
- `order_*` 对象是否按验证式顺序出现；
- `num_place` 的对象、容器实例及精确数量；
- `category_place` 的非零目标、数量和零数量对象排除；
- 明显的 `if ... else`、选项列表等分支式写法；
- house ID、`task_type`、`verify`、`self.` 和思维标签泄漏。

检查失败时，失败原因会附加到下一次提示中。每条记录最多尝试 3 次；最终故事、
剩余问题和通过状态都会写入输出，便于后续审查。

### 输出结构

```json
{
  "_index": 0,
  "house": "house_28",
  "task": "<scenario story>",
  "task_original": "<original task>",
  "verify": "<original verifier>",
  "task_type": "conditional_navigate",
  "type_num": 6,
  "meta": {
    "retries": 0,
    "problems": [],
    "passed": true,
    "verify_target_conflict": null,
    "verify_impossible_branch": false
  }
}
```

## 后续质量保障

### 反向抽取与符号等价

计划使用独立模型把故事反向抽取为与 `verify` 相同的 DSL，再进行程序化比较：

1. 将普通谓词调用规范化为命题原子；
2. 将同一计数谓词的数值比较切分为互斥区间，避免把 `> 4` 与 `<= 4` 当作
   无关变量；
3. 对有限原子集合枚举真值，检查反向抽取结果与源 `verify` 是否双向等价；
4. 不等价时保留反例赋值，并将其作为重试反馈。

### 独立 LLM 评审

使用与生成调用相互独立的评审请求，对照 `task_original`、故事和结构化约束，重点
检查确定性规则难以覆盖的问题：遗漏条件、增加动作、提前决定分支、语气歧义和误导性
背景。形式化等价和独立评审均通过后，才可标记为完整语义校验通过。

### 分层人工验收

- 每个 `task_type` 随机抽取至少 3 条；
- 对高复杂度 `logical` 任务、发生过重试的记录和带源验证式异常标记的记录提高采样率；
- 核对故事自然度、动作可执行性、完整分支语义及最终指令是否清晰；
- 若抽检通过率低于 95%，回查相应任务类型的提示词和校验规则。

## 已知边界与风险

- 正则和字符串检查只能发现机械问题，无法证明自然语言逻辑等价；
- 反向抽取本身可能出错，必须保留抽取结果、模型配置和反例以供审计；
- 源 `verify` 可能包含冲突或不可满足分支，应单独修复或明确排除，不能由故事改写
  静默改变其含义；
- 全量生成需要考虑 API 速率、成本和失败恢复；当前脚本支持批次与断点续跑，但尚未
  实现并发调度和显式速率限制；
- 任何正式发布都应保留原始任务，且不得原地覆盖源 JSONL。
